# TG Splitter

TG Splitter разбивает файлы и папки на независимые TAR-архивы для Telegram и восстанавливает их без обязательного порядка загрузки. Требуется Python 3.8 или новее. Основной размер архива — 1900 МиБ.

## 1. GUI — разбиение (Split)

Запустите окно:

```bash
python tgsplit.py
# или
python tgsplit.py gui
```

Откройте вкладку **«Разбить»**.

### Источники

- **«Добавить файлы…»** — выбрать один или несколько файлов.
- **«Добавить папку…»** — добавить папку со всем её содержимым.
- **«Убрать выбранное»** — убрать выделенные строки из списка, не удаляя сами файлы.
- **«Очистить»** — очистить весь список источников.
- Перетаскивание файлов и папок работает при установленном `tkinterdnd2`; без него доступны все кнопки.

### Параметры

- **«Папка результата»** — куда записывать архивы и план. Кнопка **«Обзор…»** открывает выбор папки. Если поле пустое, будет создана папка `имя_parts` рядом с источником.
- **«Имя NAME»** — основа имён файлов: `NAME.0001.tar`, `NAME.0002.tar` и т. д. Если пусто, используется имя источника или `archive`.
- **«Размер архива»** — максимальный размер одного архива. Обычно `1900M`, для Telegram Premium можно указать `3900M`.
- **«Сколько архивов создать сейчас»** — число архивов за этот запуск; пустое поле означает все ожидающие архивы. Остальные останутся в плане для следующего запуска.
- **«Только архивы с номерами»** — создать только указанные ожидающие архивы, например `6,7` (консольный `--only`). Нельзя сочетать с числом архивов.
- **«Пересоздать архивы с номерами»** — заново создать уже готовые архивы, например `3`, если файл потерян (консольный `--redo`). Нельзя сочетать с двумя предыдущими полями.

### Кнопки операций

- **«Показать план»** — показать состав и размеры будущих архивов без их создания. Для существующего плана просто читает `NAME.plan.json` (повторно файл не читается, пока он не изменился) и ничего не пересчитывает. Если плана ещё нет, строит его **в памяти**: это быстрый обход папок без чтения содержимого файлов. Построенный так план запоминается, и «Сохранить план» или «Разбить» с теми же параметрами запишут именно его, не сканируя источники заново. Изменили источники, размер, имя или папку результата — план построится заново.
- **«Разбить»** — построить план и начать создание архивов.
- **«Продолжить»** — появляется, если в папке результата уже есть план. Продолжает с первого ожидающего архива; список источников при этом заблокирован, чтобы случайно не изменить набор.
- **«Обновить план»** — повторно сканирует исходные папки и расширяет существующий план. По умолчанию архивы не создаются (их создаёт «Продолжить»); если отметить рядом «и сразу создать архивы», новые архивы создаются сразу, не больше числа из поля «Сколько архивов создать сейчас» (консольный `extend --max-parts`). Новые файлы и папки упаковываются только в новые архивы. Если файл был перенесён или переименован, программа распознаёт его по размеру и SHA256 и добавляет операцию переноса без повторной записи содержимого. Старые архивы и исходный `plan_id` не меняются.
- **«Добавить папку…»** (во втором ряду кнопок, при выбранном плане) — выбранная папка (например, новый год) становится новым корневым источником: её файлы попадают в новые ожидающие архивы плана, сами архивы создаёт «Продолжить», `plan_id` и старые архивы не меняются. Папка не должна лежать внутри уже добавленных источников и не должна быть папкой результата.
- **«Сохранить план»** — построить (или взять уже показанный) и записать `NAME.plan.json` без создания архивов; позже его можно продолжить кнопкой «Продолжить».
- **«Статус»** — показать, сколько архивов готово и сколько примерно осталось (консольный `status`). Мгновенно.
- **«Проверить архивы»** — сверить SHA256 присутствующих архивов с файлами `.sha256` и планом (консольный `verify`), с индикатором выполнения и возможностью отмены.
- **«Открыть файл плана»** — открыть `NAME.plan.json` программой по умолчанию. Для больших планов лучше «Открыть папку результата».
- **«Отмена»** — остановить текущую операцию. Незавершённый `.part` удаляется, а готовые архивы и план сохраняются.
- **«Открыть папку результата»** — открыть папку с созданными файлами (на вкладке «Восстановить» — папку восстановления). Доступна всегда, как только папка существует.

После отправки готовые архивы можно удалить. Для продолжения важен файл `NAME.plan.json` — **не удаляйте его**.

## 2. GUI — восстановление (Gather)

Откройте вкладку **«Восстановить»**.

### Выбор архивов

- **«Добавить архивы…»** — выбрать один или несколько файлов `.tar`. Их можно выбирать в любом порядке и понемногу за несколько запусков.
- **«Добавить папку…»** — добавить все TAR-архивы из выбранной папки.
- **«Очистить»** — очистить список выбранных архивов, не удаляя файлы.
- Перетаскивание доступно при установленном `tkinterdnd2`.

### Параметры и кнопки

- **«Куда восстановить»** — папка для восстановленных файлов. **«Обзор…»** открывает выбор папки. Если поле пустое, используется подпапка `restored` рядом с архивами.
- **«Если файл существует»**:
  - `skip` — пропустить файл и оставить существующий без изменений;
  - `overwrite` — заменить существующий файл;
  - `rename` — записать восстановленный файл под новым именем.
- **«Удалить неполные .tgspart после отчёта»** — консольный `--discard-partial`; по умолчанию неполные файлы сохраняются для продолжения.
- **«Восстановить»** — начать извлечение. В журнале появятся количество полученных архивов, полностью восстановленных и неполных файлов.
- **«Отмена»** — остановить операцию; уже записанное состояние фрагментов сохраняется.
- **«Открыть папку результата»** — открыть папку восстановления после завершения.

Недособранные файлы хранятся как `имя.tgspart`; состояние записано в `.tgsplit-restore.json`. Добавьте недостающие архивы и повторите операцию. Нельзя смешивать архивы из разных наборов с разными `plan_id`.

## 3. Консоль — разбиение (Split)

Основная команда:

```bash
python tgsplit.py split "ПАПКА" "ФАЙЛ" -o "OUT"
```

Создать только первые 5 ожидающих архивов, затем продолжить без повторного указания источников:

```bash
python tgsplit.py split "ПАПКА" -o "OUT" --max-parts 5
python tgsplit.py split -o "OUT"
```

### Добавление и перенос файлов

После изменения содержимого исходных папок выполните:

```bash
python tgsplit.py extend -o "OUT"
python tgsplit.py extend -o "OUT" --plan-only      # только обновить план
python tgsplit.py extend -o "OUT" --max-parts 3    # создать не более 3 новых архивов
```

`extend` сканирует корни из существующего плана. Новые элементы добавляются в конец набора; старые архивы не переписываются. Перенос или переименование обычного файла распознаётся по размеру и SHA256: в новый служебный архив записывается операция `move`, а при восстановлении старое содержимое получает новый путь. Это работает и для файлов из ещё не созданных архивов, и для цепочек переносов. SHA256 исходных файлов программа не считает при построении плана: он записывается в план в тот момент, когда файл попадает в архив (обычные файлы хэшируются бесплатно прямо при записи, файлы, которые режутся на фрагменты, — один раз перед нарезкой). Поэтому перенос файла, чей архив ещё не создан, распознаётся без чтения данных — по размеру и времени изменения, а перенос уже заархивированного файла — по SHA256. Планы, созданные прежними версиями (с SHA256 у всех файлов), продолжают работать без изменений.

Аргументы `extend`:

- `-o OUT`, `--output OUT` — обязательная папка с существующим планом.
- `-n NAME`, `--name NAME` — выбрать план, если их несколько.
- `--max-parts N` — ограничить число архивов, созданных именно этим расширением; остальные новые архивы останутся ожидающими.
- `--plan-only` — атомарно обновить план, но не создавать новые архивы.
- `--add ПУТЬ` — добавить новую корневую папку или файл в существующий план; можно указывать несколько раз.
- `-h`, `--help` — справка по команде.

Новую корневую папку добавляют ключом `--add` (можно несколько раз):

```bash
python tgsplit.py extend -o "OUT" --add "D:\\photos\\2027"
python tgsplit.py extend -o "OUT" --add "D:\\photos\\2027" --plan-only
```

Папка не должна лежать внутри уже добавленных источников и содержать их; файлы внутри существующих источников подхватывает обычный `extend`. Если файл перенесён между корнями, он распознаётся как перенос. Файл, удалённый после построения плана, при создании архива пропускается с записью в журнал, ошибки нет. Изменение содержимого уже отслеживаемого файла не считается новым файлом или переносом.

### Аргументы `split` и `plan`

- `PATHS...` — файлы и/или папки. У `split` их можно не указывать при продолжении существующего плана. Если указаны, они должны совпадать с планом.
- `-o OUT`, `--output OUT` — обязательная папка результата.
- `-s SIZE`, `--size SIZE` — максимальный размер архива; по умолчанию `1900M`. Поддерживаются `K`, `M`, `G` и дробные значения, например `300K`, `1.8G`; число без суффикса означает МиБ. Минимум — 64 КиБ.
- `-n NAME`, `--name NAME` — имя набора. Также выбирает нужный план, если в папке их несколько.
- `-h`, `--help` — справка по команде.

Дополнительные ключи `split`:

- `--max-parts N` — создать не более N первых ожидающих архивов.
- `--only 6,7` — создать только указанные ожидающие архивы.
- `--redo 3` — пересоздать уже готовый архив, например после его потери. Можно указать несколько номеров через запятую.
- `--redo` нельзя сочетать с `--only` или `--max-parts`; `--only` нельзя сочетать с `--max-parts`.

Сопутствующие команды:

```bash
python tgsplit.py plan "ПАПКА" -o "OUT" [-s 1900M] [-n NAME]
python tgsplit.py status "OUT" [-n NAME]
python tgsplit.py verify "OUT" [-n NAME]
```

- `plan` — построить, показать и сохранить план без создания архивов; принимает `-o`, `-s`, `-n`.
- `status` — показать число готовых архивов, примерный оставшийся размер и пропущенные источники; принимает `-n`.
- `verify` — проверить SHA256 присутствующих архивов по файлам `.sha256`; принимает `-n`. Отсутствующие архивы не считаются ошибкой.

Создаются `NAME.NNNN.tar`, `NAME.NNNN.tar.sha256` и `NAME.plan.json`. Файл `NAME.lock` блокирует одновременные операции; после аварийного завершения его можно удалить только при уверенности, что другой процесс не работает. Коды завершения: `0` — успех, `1` — ошибка, `2` — ошибка целостности, `130` — отмена.

## 5. Что считается долго, а что быстро

Тяжёлая работа выполняется один раз и в нужный момент, остальное — лёгкое:

- **Построение плана** — обход папок и упаковка в архивы; содержимое файлов не читается, поэтому для сотен тысяч файлов это секунды. В журнале пишется время каждого шага.
- **Создание архива** — единственная тяжёлая операция: каждый файл читается один раз, хэшируется и пишется в архив одновременно. После каждого готового архива план обновляется атомарно.
- **Показать план, Статус, Открыть…, чтение плана при старте** — только чтение `NAME.plan.json`, без обхода источников и без пересчёта.
- **Проверить архивы** — читает готовые архивы целиком; запускайте, когда действительно нужна проверка.

Все долгие операции GUI выполняются в фоновом потоке и поддерживают «Отмену»; окно не зависает.

## 4. Консоль — восстановление (Gather)

Восстановить все архивы из папки:

```bash
python tgsplit.py join "OUT" -o "RESTORED"
```

Восстановить выбранные архивы в любом порядке:

```bash
python tgsplit.py join "OUT\NAME.0004.tar" "OUT\NAME.0003.tar" -o "RESTORED"
```

Аргументы `join`:

- `PATHS...` — один или несколько архивов либо папок. Обязательный аргумент.
- `-o OUT`, `--output OUT` — папка восстановления; по умолчанию `restored` рядом с первым архивом.
- `--on-exist skip|overwrite|rename` — пропустить, заменить или переименовать восстановленный файл при совпадении имени; по умолчанию `skip`.
- `--discard-partial` — удалить неполные `.tgspart` после отчёта. По умолчанию они сохраняются для продолжения.
- `-h`, `--help` — справка по команде.

При восстановлении проверяются внутренние хэши элементов и внешние `.sha256`. Отсутствие sidecar-файла вызывает предупреждение, повреждение архива — код завершения `2`. Небезопасные пути и выход за папку восстановления отклоняются.
